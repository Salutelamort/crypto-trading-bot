# Внешний монитор без LLM

GitHub Actions запускает `.github/workflows/monitor.yml` по расписанию раз в пять
минут, со смещением от начала часа. Проверка выполняется вне Railway и не зависит
от компьютера владельца. Python использует стандартную библиотеку: моделей,
платных AI API, биржевых ключей и Railway-токена в этом workflow нет.

`BOT_MONITOR_URL` — обычная переменная репозитория с HTTPS-адресом `/monitor`.
Endpoint возвращает только служебные признаки: процесс работает, heartbeat свежий,
рыночные данные доступны при необходимости, сверка учёта проходит, исследование
не устарело и последняя локальная резервная копия создана. Баланс, позиции и
стратегии не публикуются. Панель и подробные API требуют пароль даже тогда,
когда переменная пароля отсутствует: без пароля они закрыты.

Проверяется не только HTTP 200, но и структура ответа, набор обязательных проверок,
время ответа и возраст heartbeat. При ошибке выполняются три попытки с паузами
15 секунд. Затем workflow завершается с ошибкой; используются стандартные
уведомления GitHub Actions, выбранные владельцем. Их доставка зависит от личных
настроек https://github.com/settings/notifications. Монитор ничего не торгует,
не меняет риск и не получает права перезапускать сервис. Восстановлением процесса
по-прежнему занимается внутренний watchdog и политика перезапуска Railway.

Ручная проверка: `gh workflow run monitor.yml`, результат — во вкладке Actions.
Испытания таймаутов и устаревших ответов входят в CI и не вызывают аварии на сервере.

Ограничения GitHub: расписание может задерживаться или пропускаться при нагрузке;
в публичном репозитории оно может отключиться после 60 дней без активности.
Поэтому это независимая проверка доступности, но не монитор с гарантированным SLA.
Проверка резервной копии относится к копии на Railway volume, а не к внешнему backup.

Документация расписания:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule
