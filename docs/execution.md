# Исполнение и отчётность audit-v3

Бот по-прежнему исполняет только локальные бумажные сделки. `experiment.id` теперь
`audit-v3`; хэши исходников и конфигурации автоматически отделяют новые входы от
предыдущих экспериментов. Открытые позиции сохраняют метки своего входа.

## Сохранение и восстановление

Один live-тик выполняется в одной SQLite-транзакции `BEGIN IMMEDIATE`: баланс,
позиции, журнал сделок и курсоры либо сохраняются вместе, либо целиком откатываются.
Соединение не должно иметь чужой незавершённой транзакции. Другой писатель ждёт
освобождения блокировки или получает ошибку до изменения данных. Сбор котировок
также входит в этот интервал блокировки; длительная недоступность сети задерживает
других писателей. Параллельные торговые процессы не нужны.

Позиция сохраняет персональные множители стопа, тейка и трейлинга, снимок настроек
риска, таймфрейм, входную комиссию, цену оценки и время её получения. Изменение
конфигурации не меняет уровни уже открытой позиции. Все открытые позиции проходят
проверку защитных выходов, даже если их агент больше не допущен или отсутствует.

Миграция только добавляет поля и не переписывает старые сделки. Для старой позиции
без снимка риска фиксируются действующие резервные настройки и появляется пометка
`legacy_risk_snapshot`. Исходные условия входа не выдаются за достоверно восстановленные.

## Минутная история

- `last_checked_at` — начало следующей необработанной минуты каждой позиции.
- Обрабатываются закрытые свечи по порядку. После каждой обновляется трейлинг.
  Внутри одной свечи порядок high/low неизвестен: при касании обоих уровней
  приоритет остаётся у стопа. При гэпе через стоп используется худшая цена открытия.
- Неполная минута входа исключается: её экстремумы могли сформироваться до входа.
  Это ограничение модели OHLC, а не точная симуляция биржевых ордеров.
- Повторы свечей не проигрываются заново. При разрыве курсор остаётся у первой
  недостающей минуты, а новые входы блокируются до восстановления данных.
- При превышении `live.max_catchup_minutes` пропуск явно отмечается и не считается
  успешно обработанным. Для восстановления необходима доступная история за разрыв;
  увеличение лимита имеет смысл только если источник может её вернуть.
- Даже при недоступности минутной истории текущая свежая цена может вызвать
  защитный выход; стоп такого выхода помечается `data_gap_stop`.
- Недоступная котировка не обнуляет стоимость позиции: сохраняется последняя
  известная оценка. Панель показывает недоступность данных и возраст последнего тика.
- Повторный вход после выхода запрещён до следующей свечи стратегии.

## Учёт и панель

`paper_trades.pnl` сохраняет прежний смысл: результат расчёта при закрытии для
возврата денег на счёт. `net_pnl` — полный результат сделки после обеих комиссий;
`cash_delta` — фактическое изменение свободного кэша. Входная комиссия не списывается
повторно. Историческая бумажная симуляция также показывает полный результат сделки.

Для старого журнала полный PnL восстанавливается только при найденном соответствующем
входе с тем же агентом, символом, режимом, экспериментом, направлением и количеством.
Неизвестный результат показан отдельно и не входит в среднее, win rate или profit
factor. Защиты от серии убытков используют полный PnL при наличии и не учитывают
исторические симуляции как live-сделки.

Карточки PnL и числа закрытий относятся к текущему эксперименту. Таблица отдельно
показывает остальные эксперименты и legacy. Equity и доходность счёта относятся ко
всему счёту. Панель также показывает причины отказов во входе, отставание свечей,
разрывы истории и сверку кэша.

Сверка начинается с явной исходной точки при первом тике новой версии. Она проверяет
баланс через сумму последующих `cash_delta`, но не доказывает корректность более
старой истории. Расхождение учёта блокирует новые входы, сохраняя защитные выходы.
Исходная точка не сбрасывается автоматически при обнаружении расхождения.

`state/latest.json` после штатного запуска получает состояние исполнения, метрики
текущего эксперимента и результат сверки. До следующего запуска старый снимок остаётся
старым. Обновление облачного кода требует отдельной публикации изменений.

## Проверки

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python tests/golden_backtest.py
python -m ruff check . --exclude data --exclude TRACK_RECORD.csv
python -m compileall -q src dashboard.py daily_learn.py main.py
```

Тесты используют временные базы и искусственные котировки; реальная торговля и сеть
для них не требуются. Эталонные результаты бэктеста не изменялись.
